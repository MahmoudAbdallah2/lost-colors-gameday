What is this quest?

🧩 The Goal

Build and deploy a multimodal AI agent that can reason over text, images, and documents, and call out to external tools (data extraction + location/maps) through a secured gateway.

🧠 The Brain

A Strands Agent backed by an Anthropic Claude model on Amazon Bedrock, running inside Bedrock AgentCore Runtime (a managed, containerized agent host).

🔌 The Hands

Two MCP (Model Context Protocol) servers exposed as tools: one for Bedrock Data Automation (document/image/video analysis) and one for Amazon Location Service (places, routes, geocoding).

🔐 The Guard

Everything is wired together with OAuth2 M2M (machine-to-machine) auth via Amazon Cognito, and locked down with a dedicated IAM execution role.

Key AI/Cloud concepts to learn here

Bedrock AgentCore
AWS's managed hosting layer for agents: it runs your agent code as a container ("Runtime"), and can front multiple tool servers behind a single secured "Gateway".
MCP (Model Context Protocol)
An open standard letting an LLM-based agent discover and call external "tools" (functions) over a standard protocol — here, HTTP/streamable MCP servers expose getprojects, analyzeasset, search_places, etc.
Strands Agents SDK
A Python framework (strands) for building model-driven agents: you give it a BedrockModel, a list of tools, and a system prompt, then stream responses.
M2M OAuth flow
"Machine to machine" — no human login. The agent runtime authenticates itself to the Gateway using a Cognito app client's own credentials (client id/secret) to get a JWT access token.
Custom JWT Authorizer
AgentCore runtimes can require a valid JWT (issued by Cognito) on every inbound call, validated against a discovery URL + allowed client ids — this is how the Gateway and MCP servers reject unauthenticated calls.
Multimodal payloads
The agent accepts a mix of text, base64-encoded images, and documents in one request, converting them into Bedrock's content-block format.
Bedrock Data Automation (BDA)
A managed AWS service that extracts structured insights from unstructured files (PDFs, images, video, audio) — exposed here as MCP tools.
Amazon Location Service
Geo/mapping APIs (geo-places, geo-routes) for search, geocoding and routing — exposed as MCP tools so the agent can reason about places.

Concepts deep-dive: Runtime vs. Gateway vs. MCP vs. Strands

🏃 AgentCore Runtime

Where the agent's own code lives and runs — a container AWS builds from your Dockerfile and auto-scales. It receives the user prompt and decides what to do.

🚪 AgentCore Gateway

A single secured front door exposing one or more MCP tool servers to any authorized runtime. Centralizes auth so tools don't each need their own.

🔧 MCP (Model Context Protocol)

A standard for exposing typed "tools" (functions) to an agent. The agent calls list_tools() to get a menu, then invokes any tool by name — no hand-written per-tool glue code.

🧵 Strands Agents SDK

The Python framework tying a Bedrock model + tool list + system prompt into a step-by-step reasoner that can decide "call a tool" vs. "answer directly" and stream output.

🔑 Cognito M2M (machine-to-machine)

No human login — the runtime authenticates to the Gateway as a Cognito app client (client id + secret) via the client-credentials grant, getting a short-lived JWT.

🛡️ Custom JWT Authorizer

Gateway/MCP servers validate that JWT against a discovery URL + allowed client id list before letting the call through — separate from IAM, which governs AWS API access.
